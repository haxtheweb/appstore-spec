Each item in `apps` is a provider definition with a `details` block (display information) and a `connection` block (how HAX talks to the provider).

<a11y-collapse heading-button="heading-button"><h2 slot="heading">details fields</h2><div slot="content"><ul><li><strong>title</strong> — provider display label.</li><li><strong>icon</strong> — icon used in the HAX UI.</li><li><strong>color</strong> — accent color for the provider card.</li><li><strong>author</strong> — provider owner / source.</li><li><strong>description</strong> — short description shown in the UI.</li><li><strong>status</strong> — provider state (commonly <code>available</code>).</li><li><strong>tags</strong> — searchable categorization terms.</li><li><strong>tos</strong> — optional terms / policy links.</li></ul></div></a11y-collapse><a11y-collapse heading-button="heading-button"><h2 slot="heading">connection fields</h2><div slot="content"><ul><li><strong>protocol</strong> — <code>http</code> or <code>https</code>.</li><li><strong>url</strong> — provider host and base path, <strong>without</strong> the protocol.</li><li><strong>headers</strong> — optional request headers.</li><li><strong>data</strong> — default query values sent with every operation.</li><li><strong>auto</strong> — optional boolean, default <code>true</code>: run the browse request as soon as the app is activated.</li><li><strong>operations</strong> — <code>browse</code> (required) and optionally <code>add</code>. HAX does not read any other operation names.</li></ul></div></a11y-collapse>

When the HAXcms platform setting disables `onlineMedia`, only apps with an `add` operation are loaded.

Build URLs the way HAX does: `protocol + "://" + url + "/" + endPoint`. So `connection.url` has no protocol, and an operation's `endPoint` has no leading slash.

Never commit real credentials. Use a `{{NAME}}` placeholder the backend fills in, or broker the request through your backend (HAXcms does this). `site_token` in `data` is sent as the `X-HAXCMS-Site-Token` header, and a HAXcms session JWT is added as an `Authorization: Bearer` header automatically.
